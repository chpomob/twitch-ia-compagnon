# Implementation Plan

## Steps

### P1: Establish the asynchronous event-bus contract and project test harness (R1; AC1–AC3)
- **Files:** [`pyproject.toml`, `core/__init__.py`, `core/bus.py`, `tests/test_bus.py`]
- **Description:** Create the Python package and its runtime/test dependencies, then implement R1 as an asynchronous `EventBus` API with `subscribe(pattern, handler, order=0)`, `publish(event_type, payload, metadata)`, and `list_events()`. Validate non-empty dot-delimited event types and whole-segment `*`/`**` patterns; make `*` consume exactly one segment and implement `**` with zero-or-more-segment matching. At publication start, build one fixed matching-handler chain from the original type and sort it by `(declared order, registration sequence)`. Await asynchronous handlers (while accepting synchronous handlers), stop on the literal result `False`, accept any other non-mapping result as no change, and validate a mapping result as a complete replacement with a valid string `type` and mapping-valued `payload` and `metadata`; preserve the entire valid replacement, including any additional fields, for downstream handlers and successful history. Raise a publication error carrying the original event type and stable handler identity when replacement validation or handler execution fails, without retaining per-publication failure state that could poison later calls. Record one finalized event only after a successful or deliberately stopped chain. This async API is an intentional architecture choice because Twitch and LLM handlers cross network boundaries; `PyYAML` and `aiohttp` provide manifest/config parsing and a single injectable HTTP/WebSocket client stack, while `pytest` and `pytest-asyncio` provide deterministic contract tests.
- **Dependencies:** []
- **Tests:** In `tests/test_bus.py`, cover AC1 wildcard examples (including zero-segment `**`), invalid empty/dotted/wildcard event names, AC2 stable order and `False` short-circuiting, and AC3 exact complete replacement propagation/history, rejection of each missing or invalid required field, identifiable handler failures, and a successful independent publication after each failure. Also verify caller payload/metadata equality when handlers return other values, sync/async handler interoperability, one history entry per successful publication, and no history entry for a failed publication.
- **Risks:** Recursive `**` matching can over-match or become exponential; use a bounded segment-index algorithm and test edge positions. Equality with `False` could accidentally stop on falsey values, so the implementation must use identity semantics. Awaiting handlers makes publication latency include business handlers by design, while audit non-blocking behavior is handled separately in P7.

### P2: Discover, validate, and activate manifest-defined modules (R2; AC4–AC6)
- **Files:** [`core/loader.py`, `tests/test_loader.py`]
- **Description:** Implement R2 in a `ModuleLoader` that examines every immediate child directory of `modules_directory`, requires and safely parses `module.yaml`, and validates all manifests before activating anything. Enforce unique non-empty names, list-valued `produces` and `consumes` whose entries are valid event patterns, Boolean `middleware`, and integer-but-not-Boolean `order` when middleware is enabled. Build a complete immutable-by-convention capability catalog keyed by manifest name and report disabled modules as discovered. Validate every enabled configuration name against discovery and require module settings mappings, then dynamically load each enabled directory’s `__init__.py` without a core name switch, call its async `activate(bus, module_settings, capability_catalog)` exactly once, and return activation records exposing an idempotent async `close()` lifecycle. Wrap discovery, field, import, and activation failures in diagnostics that include the directory or manifest name and relevant field/operation but not configuration values. This dynamic entry-point convention is a deliberate extensibility boundary required by R2/AC6.
- **Dependencies:** [P1]
- **Tests:** In `tests/test_loader.py`, construct temporary immediate-child module fixtures to prove AC4 shared-bus/settings/catalog identity and disabled-module non-activation; parameterize every AC5 malformed/missing/duplicate/unknown-enabled case and assert validation completes before any activation. Cover malformed YAML, invalid names/pattern entries, missing enabled settings, ignored nested non-immediate directories, activation exception context, and AC6 discovery/activation of an arbitrary fourth-party module with no `core/` edit.
- **Risks:** Dynamic imports can collide in `sys.modules` or accidentally import a same-named installed package; load from resolved file paths under unique internal module keys. Directory traversal and symlink behavior can broaden discovery unexpectedly, so resolve and constrain each candidate to an immediate child. A partially activated set must be retained for P3 cleanup if a later module fails.

### P3: Validate configuration and coordinate startup, readiness, signals, and shutdown (R3; AC7–AC9)
- **Files:** [`core/main.py`, `tests/test_main.py`]
- **Description:** Implement R3’s executable entry point with one required configuration-path argument and an internal async runner that can receive an injected stop event in tests. Safely load YAML, require a non-empty `modules_directory`, a list of unique non-empty `enabled_modules`, and a `modules` mapping; recursively resolve scalar strings that are exactly `${NAME}` and reject unresolved required references by setting path. Require mapping entries for enabled modules and validate non-empty `brain.endpoint`, `brain.model`, `brain.api_key` and non-empty `twitch.client_id`, `client_secret`, `access_token`, `broadcaster_id`, and `bot_user_id`. Resolve a relative modules directory against the configuration file’s directory, create one `EventBus`, invoke `ModuleLoader`, and report readiness only after every activation succeeds. Keep activation records alive until SIGINT/SIGTERM or the injected stop event, close every activated module exactly once in reverse activation order on normal termination or partial-start failure, and translate expected errors into concise non-zero CLI exits without tracebacks. Diagnostics shall name setting paths/modules/operations while never interpolating secret-bearing values; shutdown failures shall be collected and safely reported without skipping remaining modules. Signal ownership, reverse-order cleanup, and readiness timing are explicit lifecycle choices needed to make cross-module startup atomic.
- **Dependencies:** [P2]
- **Tests:** In `tests/test_main.py`, cover AC7 by asserting all three configured activations, no early return before the stop signal, one reverse-order close opportunity apiece, status `0`, and no traceback. Cover AC8 independently for unreadable/malformed YAML, non-mapping YAML, unresolved environment references, every missing/type-invalid top-level setting, a missing Twitch token, activation failure after prior success, cleanup after partial startup, non-zero status before readiness, and absence of all configured credential strings. Cover AC9 with source-tree literal searches and two runs whose YAML/environment-only endpoint, model, identity, and credential changes reach module settings unchanged. Test relative directory resolution and signal-handler cleanup without sending real process signals.
- **Risks:** OS signal APIs differ on Windows and when no main-thread event loop owns the process; isolate signal registration behind the runner and retain a testable stop-event path. Cleanup can mask the original startup error, so preserve the primary failure and append only sanitized close-operation context. Environment substitution must not dump the source configuration on error.

### P4: Implement Twitch EventSub ingestion, deduplication, recovery, and Helix sending (R4; AC10–AC13)
- **Files:** [`modules/twitch/__init__.py`, `tests/test_twitch.py`]
- **Description:** Implement the P2 activation/lifecycle convention for R4 with injectable `aiohttp` session and retry-delay seams. Validate the configured access token/client identity with Twitch authentication context before reporting activation success, establish an EventSub WebSocket, wait for its welcome session, and create the broadcaster `channel.chat.message` subscription before returning readiness. Run reception in a managed background task: validate message envelopes and event fields, publish `channel.chat.message` with payload keys for broadcaster ID, chatter ID, chatter display name, message ID, and plain text plus `metadata.source: twitch`, and add a message ID to an activation-lifetime deduplication set only when its notification has been accepted for processing. Handle Twitch reconnect instructions by transferring to the supplied URL, and recover other retryable disconnects with bounded backoff, a fresh session welcome, and subscription recreation while preserving the same dedupe set. Subscribe to `channel.chat.send`; reject missing/non-string/whitespace-only `payload.text` without a Helix call, otherwise POST one Helix chat-message request using configured broadcaster/bot identities and an optional requested `payload.parent_message_id`. Require protocol-appropriate successful statuses and response shapes for auth, subscription, receive, and send before recording success. Surface operation-specific sanitized errors, keep credential material out of exceptions/logs, and make `close()` idempotently stop reconnect/reception tasks and close all sessions.
- **Dependencies:** [P2]
- **Tests:** In `tests/test_twitch.py`, use scripted fake HTTP/WebSocket transports to cover AC10 field mapping/source metadata and duplicate suppression before and after reconnect; AC11 recoverable disconnect, new session, restored subscription, and resumed reception; AC12 exact Helix body/headers, reply parent preservation, and zero calls/success records for missing or empty text; and AC13 separate authentication, subscription, malformed envelope/event, and Helix-status failures with operation context, zero false success, and no configured client secret/token in diagnostics. Also test reconnect instructions, retry cancellation on close, non-retryable shutdown, and exactly-once lifecycle cleanup.
- **Risks:** EventSub reconnect handoff differs from reconnecting after an unplanned close: the former preserves Twitch’s subscription while the latter requires recreation, so tests must distinguish both branches. Marking IDs before a failed bus publish could lose a retry, while marking after can duplicate downstream side effects; the implementation must document and test the specified “processed” boundary. Background exceptions must be observed and surfaced instead of becoming silent task warnings.

### P5: Build capability-derived model context and atomic tagged-output routing (R5; AC14–AC16)
- **Files:** [`modules/brain/__init__.py`, `tests/test_brain.py`]
- **Description:** Implement the P2 activation/lifecycle convention for R5, subscribing to `channel.chat.message` and retaining bounded activation-lifetime conversation context keyed by viewer identifier. For each valid input, derive a deterministic system prompt at runtime by enumerating every loaded manifest’s name, `produces`, and `consumes` capabilities; combine that prompt with the current viewer/message identifiers, incoming text, and available prior conversation turns. POST one OpenAI-compatible chat request to the exact configured endpoint with the configured model and Bearer API key, validate the non-success/error and `choices[0].message.content` branches, and never hardcode a model, endpoint, or Twitch-specific route. Parse the entire output into `[send:<event.type>]` sections first, require at least one fully tagged non-empty section, validate every tag as a concrete event type permitted by the brain manifest’s declared `produces` patterns, and reject the whole model response before publishing anything if any section is unsupported, empty, or malformed. Publish valid sections in source order with `payload.text` and metadata containing `source: brain`, source message ID, and viewer ID. Diagnostics shall identify only the model operation/response defect and omit API keys, endpoint authorization data, raw unrelated prompt turns, and unrelated response content.
- **Dependencies:** [P2]
- **Tests:** In `tests/test_brain.py`, cover AC14’s one request, configured endpoint/model, catalog-derived input/output capabilities, incoming text/viewer context, and prior available conversation context. Cover AC15’s exact text and retained identifiers. Cover AC16 with two ordered recognized sections and parameterized unsupported tag, mixed valid-plus-invalid section, empty section, leading/trailing untagged content, missing/malformed choice content, timeout, transport failure, and non-success response; assert atomic zero-publication failure and sanitized diagnostics. Verify bounded separation of viewer histories, deterministic capability ordering, credential-bearing headers only on the request, and clean session shutdown.
- **Risks:** Publishing while parsing would violate AC16 atomic validation when a later section is bad, so parsing and validation must finish before the first bus call. Conversation history can grow or cross-contaminate viewers unless it is bounded and keyed. OpenAI-compatible servers vary in error bodies, so error handling must use status/shape context rather than echoing bodies or prompts.

### P6: Add non-blocking, recursively redacted catch-all audit middleware (R6; AC17–AC18)
- **Files:** [`modules/audit/__init__.py`, `tests/test_audit.py`]
- **Description:** Implement the P2 activation/lifecycle convention for R6 and register exactly one `**` handler using the audit manifest’s required order `90`. The handler shall recursively copy and redact mappings/lists/tuples at any depth when a key case-insensitively equals `authorization`, `client_secret`, `access_token`, `api_key`, `credential`, or `credentials`, serialize a single-line JSON record containing at least the event type and payload, enqueue it with a non-blocking in-memory operation, and return the original event object unchanged. A dedicated managed writer task shall perform stdout writes away from the publication chain; delayed or failed writers may emit a credential-free stderr diagnostic but may neither raise into publication nor stop later audit records from being dequeued. Use an unbounded activation-local queue so queue saturation cannot block or silently discard an event, and provide an idempotent close path that attempts orderly draining while retaining a bounded cancellation path for a permanently stuck writer. This queue/worker boundary is an explicit concurrency choice to meet R6’s “every event” and non-blocking requirements simultaneously.
- **Dependencies:** [P2]
- **Tests:** In `tests/test_audit.py`, cover AC17’s exact one-line parseable record, type/payload fields, order `90`, and identity/equality of the event seen by a later handler. Cover AC18 with delayed and exception-throwing injected writers while a downstream probe completes exactly once, plus all six sensitive key spellings distributed across top-level and nested containers with mixed casing; assert all secret values are absent, all replacements equal `[REDACTED]`, and normal chat `text` is intact. Test multiple queued events, writer continuation after one failure, non-mutation of the published event, and bounded idempotent shutdown.
- **Risks:** Writing directly in the handler or awaiting a bounded queue would violate the latency requirement. Recursive redaction must avoid mutating caller data and must define safe handling for non-JSON-native values/cycles; normalize unsupported leaves to safe representations without exposing object representations that may contain secrets, and detect cycles. A permanently blocked OS-level write cannot be forcefully ended from Python, so isolate it from publication and bound only lifecycle waiting.

## Ordering rationale

P1 defines the async event and handler semantics used everywhere else. P2 builds discovery and the module activation/lifecycle boundary on that stable bus contract. P3 then owns configuration, readiness, and shutdown around the loader. P4–P6 can be implemented independently once the activation and bus APIs exist, and each isolates one network or concurrency concern. P7 supplies the concrete manifests and example configuration after their validators and runtime expectations are known. P8 assembles the real files behind simulated external boundaries to expose contract mismatches that unit tests cannot see. P9 is last because its purpose is to inspect and test the complete branch as one integrated change before delivery.
